# Sprint S3 Entities & Money Design Review

Status: design only. Do not implement until approved.
Date: 2026-06-01
Branch inspected: `s2-feature-propagation`

## 1. Decision

**Recommendation: migrate persisted invoice money values from `double` to integer
minor units now, using a staged additive migration.**

Use `int` minor units, named `*Cents` for the current product vocabulary, while
documenting that the unit is the currency's minor unit. MYR is the default and
has 2 decimal places, so "cents" is accurate for the current primary market. The
implementation should keep old `double` fields in S3, add new integer fields
beside them, backfill, switch reads/writes/UI/PDF to the new fields, and remove
old doubles only in a later sprint after verification.

Do not use a decimal package for persisted money in S3. It would still need a
primitive ObjectBox representation and adds dependency/API surface. A lightweight
`Money` value object around `int minorUnits` gives deterministic arithmetic,
simple storage, and enough future currency support for a solo-maintained app.

## 4. Current Money Representation

Money is stored and calculated as `double`.

Examples:

- `Invoice.subtotal`, `Invoice.taxAmount`, `Invoice.total`, etc. are `double`.
- `Item.unitPrice`, `Item.costPrice`, `Item.wholesalePrice` are `double` or
  nullable `double`.
- `invoice_form_page.dart` parses text fields with `double.tryParse`.
- `invoice_form_provider.dart` computes subtotal with:

```dart
sum + (item.unitPrice * (item.stockQuantity ?? 1))
```

- `invoice_generator.dart` formats line items and totals using
  `toStringAsFixed(2)`.
- `objectbox.g.dart` writes these fields as Float64.

This is unsafe for invoice totals because binary floating point can produce
rounding drift across multiplication, tax, discount, and payment calculations.

## 5. Proposed Money Representation

Persist primitive integer minor units:

```dart
final int subtotalCents;
final int discountAmountCents;
final int taxAmountCents;
final int totalCents;
final int paidAmountCents;
final int balanceDueCents;
```

For `Item`:

```dart
final int unitPriceCents;
final int? costPriceCents;
final int? wholesalePriceCents;
```

Keep `currency` / `currencyCode` as a separate string. Invoices already have
`String? currency`; normalize to uppercase and default to settings currency,
currently MYR-focused but not hardcoded in storage.

Naming note: use `*Cents` now because the app's display and docs already speak
in two decimal places. Internally the `Money` type should call the integer
`minorUnits` so future zero-decimal or three-decimal currencies can be supported
without changing arithmetic APIs.

## 6. Lightweight Money Design

The value object should be small and dependency-free.

```dart
class Money implements Comparable<Money> {
  final int minorUnits;
  final String currencyCode;

  const Money(this.minorUnits, {this.currencyCode = 'MYR'});

  factory Money.zero({String currencyCode = 'MYR'}) =>
      Money(0, currencyCode: currencyCode);

  factory Money.fromDouble(
    double value, {
    String currencyCode = 'MYR',
    int fractionDigits = 2,
  }) {
    final scale = _pow10(fractionDigits);
    return Money((value * scale).round(), currencyCode: currencyCode);
  }

  factory Money.fromDecimalString(
    String value, {
    String currencyCode = 'MYR',
    int fractionDigits = 2,
  }) {
    final cleaned = value.replaceAll(',', '').trim();
    if (cleaned.isEmpty) return Money.zero(currencyCode: currencyCode);

    final negative = cleaned.startsWith('-');
    final unsigned = negative ? cleaned.substring(1) : cleaned;
    final parts = unsigned.split('.');
    final whole = int.tryParse(parts[0].isEmpty ? '0' : parts[0]) ?? 0;
    final fractionRaw = parts.length > 1 ? parts[1] : '';
    final padded = (fractionRaw + '0' * fractionDigits)
        .substring(0, fractionDigits);
    final fraction = int.tryParse(padded) ?? 0;
    final scale = _pow10(fractionDigits);
    final units = whole * scale + fraction;
    return Money(negative ? -units : units, currencyCode: currencyCode);
  }

  Money operator +(Money other) {
    _assertSameCurrency(other);
    return Money(minorUnits + other.minorUnits, currencyCode: currencyCode);
  }

  Money operator -(Money other) {
    _assertSameCurrency(other);
    return Money(minorUnits - other.minorUnits, currencyCode: currencyCode);
  }

  Money multiplyInt(int quantity) =>
      Money(minorUnits * quantity, currencyCode: currencyCode);

  Money percent(double rate) =>
      Money((minorUnits * rate / 100).round(), currencyCode: currencyCode);

  String format({String symbol = 'RM', int fractionDigits = 2}) {
    final scale = _pow10(fractionDigits);
    final abs = minorUnits.abs();
    final whole = abs ~/ scale;
    final fraction = (abs % scale).toString().padLeft(fractionDigits, '0');
    final sign = minorUnits < 0 ? '-' : '';
    return '$sign$symbol$whole.$fraction';
  }

  double toDouble({int fractionDigits = 2}) =>
      minorUnits / _pow10(fractionDigits);

  void _assertSameCurrency(Money other) {
    if (currencyCode != other.currencyCode) {
      throw ArgumentError('Currency mismatch: $currencyCode vs ${other.currencyCode}');
    }
  }

  @override
  int compareTo(Money other) {
    _assertSameCurrency(other);
    return minorUnits.compareTo(other.minorUnits);
  }
}

int _pow10(int exponent) {
  var result = 1;
  for (var i = 0; i < exponent; i++) {
    result *= 10;
  }
  return result;
}
```

Tax calculation:

```dart
Money calculateTax(Money taxableAmount, double taxRate) {
  return taxableAmount.percent(taxRate);
}
```

Discount calculation:

```dart
Money calculateDiscountByRate(Money subtotal, double rate) {
  return subtotal.percent(rate);
}

double calculateDiscountRate(Money subtotal, Money discount) {
  if (subtotal.minorUnits == 0) return 0;
  return (discount.minorUnits / subtotal.minorUnits) * 100;
}
```

Invoice total calculation:

```dart
class InvoiceMoneyTotals {
  final Money subtotal;
  final Money discount;
  final Money tax;
  final Money total;
  final Money paid;
  final Money balanceDue;

  const InvoiceMoneyTotals({
    required this.subtotal,
    required this.discount,
    required this.tax,
    required this.total,
    required this.paid,
    required this.balanceDue,
  });
}

InvoiceMoneyTotals calculateInvoiceTotals({
  required Iterable<Item> items,
  required Iterable<Tax> taxes,
  required Money discount,
  required Money paid,
  required String currencyCode,
}) {
  final subtotal = items.fold(
    Money.zero(currencyCode: currencyCode),
    (sum, item) => sum +
        Money(item.unitPriceCents, currencyCode: currencyCode)
            .multiplyInt(item.stockQuantity ?? 1),
  );

  final taxableAmount = subtotal - discount;
  final totalTax = taxes.fold(
    Money.zero(currencyCode: currencyCode),
    (sum, tax) => sum + taxableAmount.percent(tax.rate),
  );

  final total = taxableAmount + totalTax;
  return InvoiceMoneyTotals(
    subtotal: subtotal,
    discount: discount,
    tax: totalTax,
    total: total,
    paid: paid,
    balanceDue: total - paid,
  );
}
```

In S3, this can live in `core/money` or a focused invoice calculator. Avoid a
large domain-layer refactor.

## 7. ObjectBox Migration Strategy

Do not change an existing ObjectBox property from `double` to `int` in place.
That is not a safe automatic migration. The generated model currently stores
money fields as Float64. A type change on the same property risks generator
errors, UID confusion, unreadable data, or silent value loss.

Use additive fields first:

Stage A: add integer fields beside old double fields.

```dart
final int? subtotalCents;
final int? discountAmountCents;
final int? taxAmountCents;
final int? totalCents;
final int? paidAmountCents;
final int? balanceDueCents;
```

Use nullable ints for the first migration commit so existing rows can open before
backfill. After backfill and read-path fallback are proven, decide whether to
make them non-null with defaults in a later commit.

Stage B: backfill cents from doubles.

Backfill formula:

```dart
int centsFromDouble(double value) => (value * 100).round();
```

Backfill should run once at startup after ObjectBox opens, or lazily at
repository read/write boundaries. Prefer a one-shot migration runner for S3
because it is explicit and testable.

Stage C: switch all reads/writes/calculations/display/PDF to integer fields.

During this stage, helper getters can bridge old data:

```dart
int get effectiveTotalCents => totalCents ?? (total * 100).round();
```

Writes should dual-write for rollback:

```dart
totalCents: totals.total.minorUnits,
total: totals.total.toDouble(),
```

Stage D: verify with tests, analyzer, manual smoke, and sample invoice comparison.

Stage E: remove old double fields later, not in S3 unless a separate backup and
restore rehearsal proves it safe. Removing old fields should use ObjectBox UID
retirement rules and should happen after at least one release/validation window.

- Adding ObjectBox fields requires regenerating `objectbox.g.dart` and
  `objectbox-model.json`.
- Commit entity changes and generated ObjectBox files together.
- Only one branch/session should generate ObjectBox model changes at a time.
- Do not hand-edit `objectbox.g.dart`.
- Preserve generated UID guidance if ObjectBox asks for `@Property(uid:)`.

Backup/export precautions:

- Before first S3 migration run, back up the app documents directory containing
  the ObjectBox store. Current code opens the store at
  `getApplicationDocumentsDirectory().path`.
- Make a copy of the `objectbox/` data files where present, or the entire app
  documents directory for simplicity.
- For manual QA, test S3 on a copied store before opening a real user store.
- If an export-to-JSON path exists later, run it before Stage C. It does not
  exist in the inspected codebase today.

## 8. Backward Compatibility Strategy

S3 must read old rows and new rows.

Rules:

- New `*Cents` fields are nullable at first.
- Add effective getters or mapper helpers that prefer cents and fall back to
  doubles.
- Backfill old rows automatically.
- Dual-write cents and doubles throughout S3.
- Keep `toMap` / `fromMap` tolerant of both old and new keys.
- UI should parse user-entered decimal strings directly to `Money`, not to
  `double`, after Stage C.

Example:

```dart
int get effectiveSubtotalCents => subtotalCents ?? (subtotal * 100).round();

Money get subtotalMoney => Money(
  effectiveSubtotalCents,
  currencyCode: currency ?? 'MYR',
);
```

## 9. Rollback Strategy

Safe rollback depends on retaining old double fields in S3.

Rollback by stage:

- After Stage A only: revert entity/generated-file commit. No read/write switch
  has happened.
- After Stage B: revert code and generated files. Old double fields still contain
  the original values plus any dual-written values.
- After Stage C/D: revert code to double reads if needed; because writes dual
  write doubles, newly edited invoices remain readable by the old app.
- Do not remove old doubles in S3. That keeps rollback practical.

Data restore:

- If generated model changes or migration code behaves unexpectedly, close the
  app, restore the pre-S3 ObjectBox backup, then run the pre-S3 app.
- If a later sprint removes old double fields, rollback requires either a reverse
  migration from cents to doubles or backup restore.

## 10. Risk Register

| Risk | Probability | Impact | Mitigation |
|---|---:|---:|---|
| ObjectBox type migration corrupts money fields | Medium | High | Do not type-change in place; add new integer fields. |
| Backfill rounds differently than UI/PDF | Medium | High | Centralize parse/round/format in `Money`; add golden sample tests. |
| Dual-write divergence between old doubles and new cents | Medium | Medium | All writes go through one calculator; test conversion and repository writes. |
| Invoice form keeps using `double.tryParse` in a forgotten path | High | Medium | Audit with `rg "double.tryParse|toStringAsFixed|unitPrice|total"` before final. |
| PDF totals differ from UI totals | Medium | High | PDF consumes invoice cents/effective `Money`, not recalculated doubles. |
| Tax rounding disputed per line vs invoice total | Medium | Medium | S3 decision: calculate taxes on taxable invoice subtotal and round each tax line to cents. Document this. |
| Existing `ObjectBoxResponse` local-source internals mask migration failure | Low | Medium | Repository returns `Result`; migration runner should return/report `Result`. |
| Generated ObjectBox files changed by parallel work | Medium | Medium | Single writer; inspect `git status`; commit generated files with entity changes. |
